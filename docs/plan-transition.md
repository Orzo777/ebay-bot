## Частина 2. Свій сервер (Oracle Cloud, безкоштовно) і закритий GitHub — грудень–січень

**Навіщо:**
1. Закрити репозиторій: бот витрачає ~30 000 хвилин GitHub Actions на місяць; приватний репозиторій без свого
   сервера — ~$200+/міс. Зі своїм сервером хвилини безкоштовні.
2. Умови GitHub Actions розраховані на збирання коду, а не на цілодобового бота (eBay-сторож — 50 хв щогодини) —
   свій сервер прибирає цей ризик.

**Що візьмемо:** Oracle Cloud **Always Free** — сервер ARM (Ampere): беремо 2 ядра і 12 ГБ пам'яті з безкоштовних 4 / 24.
Ціна — **0 €**, якщо не виходити за безкоштовні ліміти (поставимо ліміт бюджету 1 € зі сповіщенням).

**Час:** ~40 хв твоїх (реєстрація може затягтися на день — це нормально). Найкраще — увечері, нікуди не поспішаючи.

### Етап 1 — 👤 реєстрація в Oracle (~15 хв + очікування)

1. Відкрий `oracle.com/cloud/free` → **Start for free**.
2. **Country:** Germany. Ім'я — як у паспорті. **Email** — нова пошта проєкту. Підтверди лист.
3. Придумай пароль. **Cloud Account Name** — коротко латиницею, наприклад `ebaybot` + цифри (його потім вводиш
   при вході — запиши).
4. **Home Region: Germany Central (Frankfurt)** — ⚠️ змінити потім не можна, безкоштовні сервери працюють лише
   в домашньому регіоні.
5. Адреса, телефон (прийде SMS).
6. **Банківська картка** — справжня, на твоє ім'я. Oracle заблокує ~1 € і поверне. Без цього реєстрація не проходить.
7. Погодься з умовами → **Start my free trial**. Лист «Your account is ready» може прийти за кілька хвилин або до доби.

Якщо Oracle відмовить без пояснень (буває) — пиши «oracle відмовив», беремо запасний варіант (Hetzner, унизу).

### Етап 2 — 👤 захист від рахунків (~5 хв)

Увійди: `cloud.oracle.com` → Cloud Account Name → email і пароль.

1. **Pay As You Go** (щоб безкоштовний сервер не забрали як «простоюючий»; поки в межах лімітів — 0 €):
   ☰ (меню ліворуч угорі) → **Billing & Cost Management** → **Upgrade and Manage Payment** →
   **Upgrade your account** → **Pay As You Go** → підтверди. Перехід займає від кількох хвилин до доби — прийде лист.
2. **Ліміт бюджету:** ☰ → **Billing & Cost Management** → **Budgets** → **Create Budget**:
   - Name: `free-guard`; Budget amount: **1** (EUR);
   - Threshold: **Percentage of budget** → **1** %; Email: нова пошта → **Create**.
   Якщо колись хоч щось почне коштувати гроші — одразу прийде лист.

### Етап 3 — 👤 ключ для входу на сервер (~2 хв)

У PowerShell:
```
ssh-keygen -t ed25519 -f "$HOME\.ssh\ebaybot"
```
Двічі **Enter** (без пароля). Потім скопіюй **публічну** частину:
```
Get-Content "$HOME\.ssh\ebaybot.pub" | Set-Clipboard
```
Файл без `.pub` — секретний: нікому не надсилай і нікуди не вставляй.

### Етап 4 — 👤 створити сервер (~10 хв)

☰ → **Compute** → **Instances** → **Create instance**:

1. **Name:** `ebay-bot-runner`.
2. **Image and shape** → **Edit**:
   - **Change image** → **Ubuntu** → **Canonical Ubuntu 24.04** → **Select image**;
   - **Change shape** → **Ampere** → **VM.Standard.A1.Flex** → **Number of OCPUs: 2**, **Amount of memory: 12 GB** →
     **Select shape**. Має бути позначка «Always Free-eligible».
3. **Networking:** лишити «Create new virtual cloud network» і «Create new public subnet»; **Assign a public IPv4
   address — Yes**.
4. **Add SSH keys** → **Paste public keys** → **Ctrl+V** (ключ з етапу 3).
5. **Boot volume** — не чіпати (≈47 ГБ, безкоштовно до 200).
6. **Create**. Через 1–2 хв статус **Running**. Скопіюй **Public IP address** (на сторінці сервера).

**«Out of capacity for shape VM.Standard.A1.Flex»** — вільних ARM-серверів зараз немає:
- у тому ж вікні **Placement** → **Edit** → інший **Availability domain** (AD-1 / AD-2 / AD-3) → знову **Create**;
- не вийшло — спробуй увечері чи вранці (місця звільняються); після Pay As You Go зазвичай легше.

➡️ Напиши **«готово VPS» + IP-адреса** (IP — не секрет).

### Етап 5 — 🤖 налаштування сервера (сам, з цього ПК, ~30 хв)

- вхід за ключем `ebaybot`, оновлення системи, окремий користувач для бота, брандмауер (лише SSH);
- виконавець GitHub Actions для ARM як служба (сам стартує після перезавантаження сервера);
- workflow переводжу на сервер по одному й перевіряю: eBay-сторож, пошта KA, «продати», звіти, посилки;
- GitHub-хмару лишаю запасною: якщо сервер упаде, workflow можна повернути назад однією зміною.

### Етап 6 — 👤 закрити репозиторій (~1 хв)

GitHub → репозиторій → **Settings** → **General** → унизу **Danger Zone** → **Change visibility** →
**Make private** → підтвердь назвою репозиторію.

### Етап 7 — 🤖 перевірка

- сторож версій (зараз читає код із відкритого GitHub) — переводжу на доступ із токеном;
- усі боти й workflow працюють, хвилини GitHub — 0; повідомлю в бот.

### Запасний варіант — Hetzner (~4–6 €/міс)

Якщо Oracle відмовив або кілька днів «Out of capacity»:
1. `hetzner.com/cloud` → **Registrieren** (нова пошта), підтвердження особи, спосіб оплати.
2. Ключ — той самий з етапу 3.
3. **New project** «ebay-bot» → **Add Server**: Location Nürnberg / Falkenstein; Image **Ubuntu 24.04**;
   Type **CX22**; **SSH keys** → **Add SSH key** → Ctrl+V; Name `ebay-bot-runner` → **Create & Buy now**.
4. Далі — так само: «готово VPS» + IP → етапи 5–7.
