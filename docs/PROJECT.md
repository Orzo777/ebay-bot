# ebay-bot — повний опис проєкту

Живий документ: оновлюється після кожного апгрейду (розділ «Журнал змін» внизу). PDF-версія збирається командою
`python tools/make_overview_pdf.py --all` → `docs/ebay-bot-overview.pdf` і шпаргалки `docs/guide-*.pdf`.

Останнє оновлення: 09.10.2026.

## 1. Мета

Особистий інструмент перепродажника в Гамбурзі з бюджетом близько 1 000 €. Бот шукає вигідну оперативну пам'ять (RAM)
і консолі (Xbox Series X, PS5, Nintendo Switch 2) у приватних продавців на Kleinanzeigen (KA) і eBay.de,
відсіює шахраїв, рахує заробіток після всіх витрат, веде облік покупок і продажів, готує оголошення на продаж і сам стежить
за своїм здоров'ям.

Принципи, з яких виросли всі рішення:

- **Точність важливіша за кількість.** Краще пропустити угоду, ніж показати невигідну чи шахрайську.
- **Бот нікому не пише сам.** Тексти продавцям лише готуються для копіювання в один дотик; купує і пише людина.
- **Без обходу захисту.** Списки пошуку KA бот не відкриває (заборонено robots.txt) — лише листи підписок і окремі сторінки
  оголошень; капчі не проходить.
- **Публічний репозиторій.** У логах GitHub — жодних сум і даних обліку; облік передається між сервісами зашифрованим.
- **Мінімум ручної роботи.** Облік заповнюється сам із листів, сторож сам перезапускає збої і пише, що оновити.

## 2. Як усе з'єднано

```
Kleinanzeigen (28 збережених пошуків) --лист--> Gmail --> Apps Script check() щохвилини --> GitHub ram_mail_alert --> картка
eBay.de Browse API <-- ebay_watch (без перерви, ланцюжком по 55 хв) ---------------------------------------------> картка
Telegram «поділитися» --> Apps Script doPost --> GitHub ka_share --> відповідь у той самий чат
бот «Облік і продаж» --> doPost ?bot=office --> ledger.gs (Google-таблиця) --> sell.yml / weekly_report.yml (зашифровано)
Gmail: листи eBay/KA про покупки, доставки, продажі --> ledger.gs кожні 15 хв --> таблиця «Облік перепродажу»
Gmail: відповіді продавців KA --> kafilter.gs кожні 5 хв --> шахраї в кошик, чесні - реплаєм на картку з перекладом
сторож: watchdog.gs кожні 10 хв + незалежна щогодинна перевірка в ebay_watch + щоденний звіт о 9:00
сторож цін: price_refresh щодня --> research/ram_prices.json (ціни продажу і стелі купівлі)
```

Де що працює:

| Частина | Де | Що робить |
|---|---|---|
| Python-код (research/) | GitHub Actions, публічний репозиторій | оцінка, картки, eBay-сторож, звіти, сторож цін, «продати» |
| Google Apps Script (tools/*.gs) | акаунт Google користувача | сигнал «є лист KA», вебхук ботів, облік, фільтр відповідей, сторож |
| Google-таблиця | Google Drive | облік перепродажу |
| Три Telegram-боти | Telegram | основний (покупки), «Облік і продаж», ПК-бот |
| Gemini (безкоштовний рівень) | Google AI Studio | перевірка фото, розбір відповідей продавців |

## 3. Джерела купівлі

### 3.1 Kleinanzeigen — підписки

- 28 збережених пошуків: DDR4/DDR5 (настільна і ноутбучна, різні об'єми), Xbox Series X, PS5, Switch 2 — по всій
  Німеччині з пересилкою і окремо в Гамбурзі (+30 км) для самовивозу.
- KA надсилає лист на кожен збіг; Apps Script щохвилини бачить новий лист і запускає перевірку в GitHub.
- Перевірка читає з Gmail лише нові листи (заголовки спершу, повний лист — тільки для нових), розбирає назву і ціну,
  відкриває одну сторінку оголошення (продавець, опис, поточна ціна, фото, «Direkt kaufen»).
- **З 02.10 — лише оголошення з «Direkt kaufen»** (оплата через KA із захистом покупця) **або з підписок «самовивіз у
  Гамбурзі»** (готівка після огляду). Продавці «лише повідомлення» майже завжди виявлялись шахраями. Вимикається
  змінною `KA_REQUIRE_BUY_NOW=0`. Скільки вигідних угод відкинуто через це — видно в щоденному звіті.
- **Консолі — лише з «Direkt kaufen», без винятку для самовивозу (з 05.10)**: у підписках «… in Hamburg» шахраї ставлять
  Гамбург і ціну на половину ринку; консоль звідти рахується як звичайна (з пересилкою). Самовивіз без «Direkt kaufen»
  лишився лише для пам'яті. Повернути — `KA_CONSOLE_PICKUP=1`.
- Картка, що прийшла пізніше ніж за годину після листа, позначається «запізніла» і шлеться лише для найкращих угод.

### 3.2 eBay.de — сторож

- Через офіційний Browse API (ліміт 5 000 запитів на добу, використовується ~3 400).
- Нові оголошення «Sofort-Kaufen» з RAM і консолями кожні ~3 хвилини, зниження цін, аукціони за 2–20 хвилин до кінця
  (перевірка ~раз на 6 хвилин) — картка з максимальною ставкою.
- Ті самі оцінювачі й стелі, що для KA; фото перевіряються ДО надсилання.
- Працює без перерви: кожен запуск GitHub Actions триває ~55 хвилин і сам запускає наступний.

### 3.3 «Поділитися → бот»

Будь-яке посилання KA чи eBay, надіслане в основний бот, отримує повну оцінку: тип, заробіток, ризик шахрайства, фото,
текст продавцю. Оголошення без «Direkt kaufen» отримують попередження.

### 3.4 ПК-бот

- Окрема підписка «PCs in Hamburg (+20 km)», приватні, **150–650 €** (з 03.10; до того 0–60 € давала лише мотлох).
- Оцінка: продати цілим або розібрати на деталі — відеокарта (31 модель), процесор (i5/i7/i9 8–13 покоління, Ryzen 5/7/9),
  RAM за щоденними цінами сторожа (16–64 ГБ, DDR5), SSD, решта корпусу одним лотом.
- Для ПК від 150 € читається опис (головне часто тільки там); картка «ТОРГУЙСЯ — вигідно до ~X €», якщо після знижки
  до 25% виходить 30% заробітку до вкладеного.
- Відсіюються міні-ПК, моноблоки, ноутбуки, тонкі клієнти, старе залізо (DDR2/DDR3, Core 2, i-2…5 покоління).

## 4. Оцінка угоди

### 4.1 Що купуємо

- **RAM**: настільна (UDIMM) і ноутбучна (SO-DIMM), DDR4 і DDR5, кіти 2×8 … 2×48 і одиночні планки — лише типи, що
  реально продаються на eBay.de з маржею (заміри Terapeak 21–26.09). Серверна (Registered ECC) — ні.
  ECC без буфера (ECC UDIMM: HMA…U7, M391A, наклейка PC4-xxxxV-Ex1) — окремий тип: оцінка як звичайна −15%,
  у «продати» — назва з «ECC Unbuffered» і конкуренти серед ECC.
- **Консолі**: Xbox Series X, PS5 Disc/Digital (Pro — ні), Nintendo Switch 2. Першу Switch (V1/V2, OLED, Lite) з 04.10
  не купуємо: бот її розпізнає, щоб не сплутати зі Switch 2, і відкидає (`SWITCH1_ON=1` — повернути).

### 4.2 Як рахується

- Розбір назви: покоління, тип (настільна / ноутбучна / серверна), об'єм, кількість планок, бренд; номери моделей
  (Samsung M4xx = ноутбучна, HMA…R7 = серверна тощо); варіанти написання, з якими ловились помилки на ~3 000 живих
  оголошень (14 проходів аудиту 28–29.09).
- Ціни продажу — реальні продажі eBay.de з Terapeak: «швидкий продаж» (p25) і медіана. Щодня їх зсуває сторож цін.
- Повна вартість купівлі: ціна + пересилка + плата «Sicher bezahlen» (або дорога на самовивіз ~5–6 €).
- Витрати продажу: комісії eBay немає (приватний продавець, продаж у Німеччині безкоштовний — довідка eBay і Verify
  «Final Value Fee waived», з 09.10; до того модель брала 6,5% + 0,45 €), DHL Paket 2 кг із відстеженням, пакування, страховка понад 500 €,
  запас на повернення.
- Стеля купівлі = ціна, за якої заробіток — 30% до вкладеного при швидкому продажу.
- Вердикти: **БЕРИ** (вигода висока), **МОЖНА** (помірна, +30–60% до вкладеного), **ТОРГУЙСЯ** (вигідно після знижки —
  з готовим текстом пропозиції), інакше картки немає.
- Опис уточнює оцінку: ноутбучна, «ціна за штуку», «шукаю», дефект, серверна, лише планшет Switch без дока тощо.

### 4.3 Сторож цін

- Щодня порівнює поточні ціни eBay з опорними і зсуває ціни продажу: вниз до −10% за день, вгору до +5%, згладжено
  медіаною з трьох днів. Різкі зміни — повідомлення в бот «Облік і продаж».
- Раз на місяць перевіряє кандидатів у нові категорії.

## 5. Захист від шахраїв і поганих угод

- **Сторінка оголошення KA**: вік акаунта, опис, що кличе в WhatsApp/Telegram/e-mail, оплата «PayPal Freunde» чи переказом
  (з маскуванням «Pay Pal», «PP», «F+F»), відмова від «Sicher bezahlen», відомий текст-шаблон шахраїв, «легенди»
  (за кордоном, лише пересилка, переїзд), ціна нижче 40–75% ринку від молодого акаунта. Жорсткі ознаки — картки немає.
- **Дефекти**: «defekt», «für Bastler» і симптоми без цього слова (вимикається, перегрів, не читає диски, синє світло).
- **Фото (Gemini)**: наклейка пам'яті проти назви (29.09: «32 GB», а на фото 4×4 GB), настільна чи ноутбучна,
  покоління, модель консолі, лише коробка / аксесуар, з 03.10 — серверна пам'ять (коди RE1/RA0, чип регістра).
  На eBay розбіжність — картки немає; на KA картка редагується (серверна — згортається в один рядок).
- **Серверна RAM (03.10)**: за назвою (коди наклейки PC4-xxxxV-Rxx), за описом (HMA…R7, M393, MTA…72P, «Registered»)
  і за фото.
- **Відповіді продавців (kafilter.gs)**: шахрайські листи («haben Sie PayPal?», WhatsApp, переказ) — у кошик Gmail;
  чесні — в основний бот реплаєм на ту картку, з якої писав користувач, з перекладом і суттю (погоджується, торгується,
  продано, «акаунт зламали»).

## 6. Картки в Telegram

Основний бот, картка угоди містить:

- вердикт і заробіток (+% до вкладеного), повну вартість купівлі;
- позначку «Є Direkt kaufen»;
- ризик шахрайства з причинами, рядок перевірки фото;
- німецький текст продавцю (одна кнопка «скопіювати») і текст пропозиції ціни для «ТОРГУЙСЯ»; з «Direkt kaufen» —
  лише текст зі знижкою (для «МОЖНА» / «ТОРГУЙСЯ»);
- кнопки: відкрити оголошення, інші збіги підписки.

Відповідь продавця приходить реплаєм на картку (з 02.10). З 06.10 переписка сама прибирається з чату, коли куплено
(облік записав покупку з KA) або оголошення зняте (щогодинна перевірка сторінки); старші 48 год — згортаються в один рядок.

Картка аукціону eBay «жива» (з 06.10): щокола (~3 хв) поточна ставка, скільки лишилось і чи ще вигідно; після кінця —
«🏁 завершено» з фінальною ставкою.

## 7. Облік і продаж (бот «Облік і продаж»)

- **Облік у Google-таблиці заповнюється сам** із листів eBay/KA: покупка, відправлення, доставка, скасування, продаж.
  Ручні команди: `купив`, `продав`, `облік`, `витрата 50 стенд` (з 04.10: аркуш «Витрати» — обладнання, пакування,
  пересилка; у «Підсумку» — «Прибуток після витрат»).
- **`продати N`** — готове оголошення eBay.de для рядка обліку: визначення товару, конкуренти (без нових продавців
  і неактивних), план ціни, назва й опис для копіювання. `виставив N [ціна]` — відмітка про виставлення.
- **Автопублікація (з 09.10)**: `ebay вхід` один раз — бот дає посилання на дозвіл eBay, користувач входить, тисне «Agree» і
  вставляє адресу сторінки з `?code=…`; GitHub міняє код на ключ (refresh token, ~18 міс.) і шифровано повертає його в Apps
  Script (Script Properties; у GitHub і в журналах ключа немає). Далі на картці «продати N» — «🚀 Виставити на eBay
  автоматично» → «✅ Так» → фото з обліку → eBay, VerifyAddFixedPriceItem (помилки — у бот, нічого не публікується) →
  AddFixedPriceItem (Trading API: Sofort-Kaufen, Preisvorschlag з порогами картки, DHL Paket за рахунок покупця, без
  повернення, «Gebraucht») → посилання на оголошення, статус «Виставлено» з номером eBay. `ebay тест N` — лише перевірка.
  Повторне натискання протягом 15 хв і вже виставлене / продане — відмова.
- **Дії в eBay кнопками (з 10.10, research/ebay_actions.py, той самий ключ)**: `відправив N трек` / `трек N …` для проданого
  на eBay → трек у замовлення (CompleteSale: «Versendet», покупець бачить відстеження); під питанням покупця —
  «📨 Надіслати відповідь» (чернетка Gemini німецькою → AddMemberMessageRTQ); під пропозицією ціни — «✅ Прийняти /
  🔁 Зустрічна / ✖️ Відхилити» (RespondToBestOffer; зустрічна — середина між пропозицією і ціною, не нижче порогу
  автоприйняття); у тижневому звіті для залежаного виставленого — «⬇️ №N → X €» (ReviseFixedPriceItem, пороги
  Preisvorschlag у тих самих пропорціях, ніколи не вище поточної ціни). Замовлення / оголошення / питання / пропозицію
  знаходимо за номером eBay з нотаток, SKU «ledger-N» або схожістю назви; пропозицію — лише на ту саму суму.
- **Межі підписок KA (з 10.10, research/ka_bounds.py)**: рекомендований «Preis bis» кожної підписки — найвища ціна, за якої
  бот ще скаже «торгуйся» (живі ціни). Тижневий звіт показує розбіжності > 5%, команда `межі` — усі; користувач міняє в KA
  і тисне «✅ Межі в KA оновив» → ka_bounds.yml записує їх у research/ka_bounds.json (ram_mail_check бере звідти).
- **Щоденний звіт о 9:00**: аптайм ботів, листи KA → картки, відкинуті без «Direkt kaufen», фото-перевірки,
  використання API, збої.
- **Тижневий звіт (понеділок)**: гроші, точність прогнозів ціни продажу, що залежалось, які підписки дають картки.
- **Захист покупок і нагадування (з 04.10), щодня о 10:00 «На сьогодні»** — лише коли є що робити:
  - посилка не йде: KA — на 5-й і 8-й день (проблему в «Sicher bezahlen» можна заявити лише 10 днів від відправки,
    на 14-й гроші самі йдуть продавцю); eBay — на 10-й і 20-й день («Artikel nicht erhalten», 30 днів після очікуваної
    доставки);
  - посилка прийшла (лист або «отримав N»): одразу — як протестувати (RAM / консоль / ПК) і до якої дати можна заявити
    проблему; через 2 дні, якщо не «перевірив N» — ще раз; «проблема N» — покроково, як заявити;
  - продано: «відправ і завантаж трек» наступного дня і ще раз через день, поки не «відправив N»;
  - заплановане: HDD 15.10, ПК-бот 17.10, звірка цін з реальними продажами щомісяця з 25.10, Thule 15.11; свої —
    «нагадай 20.10 текст», список — «нагадування»; 8+ продажів за 30 днів → нагадування про варіант А і податкові пороги;
  - PS5 у новій покупці → підказка спробувати Amazon.
- **Фото товару (з 08.10)**: фото в бот «Облік і продаж» з підписом-номером («3») зберігаються до рядка (file_id Telegram),
  повідомлення з фото прибирається, підсумок по рядку — одне повідомлення, що оновлюється. Gemini читає фото: наклейка → звірка
  з покупкою (модель, DDR, ПК/ноутбук, ГБ на планку, Registered); екран MemTest86 «Errors: 0» після проходу → «Перевірено»,
  помилки → «Проблема». «продати N» — альбом фото слідом за оголошенням; «фото N» — показати. Без номера: єдиний товар на
  руках або питання «до якого товару?».
- **Відстеження посилок (з 06.10)**: трек-номер — з листа eBay/KA «відправлено» (бот пише «🚚 відправлено» з кнопкою
  відстеження) або командою `трек N номер`; листи DHL / Hermes / DPD / GLS / UPS зараховуються лише за відомим треком (особисті
  посилки не чіпаються і не логуються): «доставлено» → «Отримано» + як протестувати, «у відділенні / Packstation» → забери.
  Продаж: `відправив N трек` → «✅ доставлено покупцю»; не доставлено за 7 днів — нагадування з посиланням на трек.

### Бот «Помічник» (з 10.10)
Окремий бот у Telegram: кидаєш оголошення (посилання KA/eBay, текст, фото) з питанням — за 1–2 хв відповідь. Apps Script
(ledger.gs, assistMessage) шифрує питання, фото (альбом збирає ~15 с), 6 останніх відповідей і короткий облік → GitHub
assist.yml → research/assist.py запускає **Claude Code** (`claude -p`, ключ CLAUDE_CODE_OAUTH_TOKEN з підписки користувача)

  заробіток» окремим рядком.

- Облік: якщо eBay обрізав назву в темі листа («Corsair Vengeance LP...»), повна назва береться з тексту листа —
  інакше категорія виходила «Інше», а «продати N» не впізнавав товар. Потрібна заміна ledger.gs в Apps Script.
- ECC без буфера (ECC UDIMM) — окремий тип пам'яті: розпізнавання за номерами (SK Hynix HMA…U7, Samsung M391A/M324R,
  Micron MTA…72AZ, Kingston KSM…E, Crucial CT…G4WF), кодом наклейки (PC4-xxxxV-EE1) і словами «ECC UDIMM / unbuffered /
  ungepuffert»; оцінка — як звичайна того ж об'єму −15%; примітка в картці; перевірка фото не плутає її з серверною;
  «продати N» пише «ECC Unbuffered» і шукає конкурентів серед ECC. Samsung M391A більше не вважається серверною.
  Привід: покупка eBay «2x16GB SK Hynix DDR4 2666 (HMA82GU7CJR8N)», продавець писав «Non-ECC».
