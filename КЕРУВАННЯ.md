# eBay-бот — керування та що відбувається

Папка проєкту: `D:\ebay-bot`

---

## 1. Що це і як працює (коротко)

Бот раз на 30 хв опитує офіційний eBay Browse API (німецький ринок, EUR) по
списку з ~34 категорій, будує **власну базу цін** по кожному товару і — після
періоду розвідки — надсилає в Telegram сповіщення про **аномально дешеві**
пропозиції.

Дві осі оцінки кожного лота:

| Вісь | Питання | Джерело |
|---|---|---|
| **ЦІНА** | дешевше за історичну медіану ЦЬОГО товару? | власна база `price_history.json` |
| **ЛІКВІДНІСТЬ** | його взагалі швидко купують? | швидкість зникнення лістингів (проксі продажів) |

Сповіщення надсилається, якщо спрацював **ціновий** детектор. Ліквідність його
**не блокує** — лише додає мітку `OK / MEDIUM / LOW / UNKNOWN` і посилання на
завершені продажі для ручної перевірки.

## 2. Хронологія: що коли відбувається

### Фаза 1 — РОЗВІДКА (`DISCOVERY_MODE=true`, зараз увімкнено). ~7 днів.

- Бот кожні 30 хв збирає ціни й життєвий цикл лістингів у `price_history.json`.
- **У Telegram НІЧОГО не надсилається.** Кандидати-аномалії пишуться рядками
  в `discovery_log.jsonl`.
- День 0–2: база порожня, майже все «накопичення історії».
- День 2–5: по популярних товарах уже є медіана (потрібно 3 спостереження за
  14 днів) → зʼявляються кандидати, але ліквідність ще `UNKNOWN`.
- День 5–7: ліквідність починає заповнюватись (потрібно 10 днів відстеження,
  тож частина лишиться `UNKNOWN` і на 7-й день — це нормально).

### Перехід (робиш ти, вручну, ~день 7)

```bat
cd D:\ebay-bot
python main.py --discovery-report
```

Це друкує таблицю по категоріях + зберігає `discovery_report.md`:
- скільки кандидатів знайшлось, який розподіл по ліквідності (OK/MED/LOW/UNK);
- **`score`** = (кандидатів/тиждень) × (частка з ліквідністю OK+MEDIUM);
- категорії відсортовані за `score`, найкращі зверху;
- унизу — готовий звужений блок `CATEGORIES` (score>0, частка OK+MED ≥ 0.4).

**Що зробити зі звітом:**
1. Скопіювати рекомендований `CATEGORIES` з хвоста звіту в `config.py`
   (підставити `min_price` — вони вже є в поточному конфізі).
2. Категорії зі `score = 0` і купою `UNKNOWN`/`LOW` — прибрати.
3. У `.env` поставити `DISCOVERY_MODE=false`.
4. Перезапустити бота (`stop.bat`, потім `run.bat`).

### Фаза 2 — БОЙОВИЙ РЕЖИМ (`DISCOVERY_MODE=false`)

- Бот так само кожні 30 хв опитує API, дописує базу.
- Коли новий лот дешевший за `ANOMALY_THRESHOLD` (0.6) × історична медіана
  його товару — **надсилає сповіщення в Telegram**.
- Кожен `item_id` сповіщається один раз (дедублікація).
- Раз/двічі на тиждень варто перезапускати `python main.py --discovery-report`
  щоб бачити, які категорії реально працюють, і підчищати список.

**Приклад A — товар звірено з каталогом (epid), попит підтверджено:**

```

ключ: epid:26058901

LEGO 10307 Eiffelturm Paris 10001 Teile - NEU & OVP versiegelt
Стан: Neu (conditionId 1000)

Нижче медіани на: 34%
Продавець: bricks_and_more (score 1842, 99.8%)

Ліквідність (власний proxy, вікно 30 дн.):
  рівень: OK — швидко продається

  швидкість: 2.4/тиждень   медіанний час до зникнення: 8 дн.

ключ: t:new:151-box-pokemon
⚠ товар визначено ЗА НАЗВОЮ (немає epid) — нижча впевненість

Pokemon 151 Elite Trainer Box EN Englisch NEU versiegelt Karmesin Purpur

Історична медіана (6 спост. / 14 дн.): 74.00 EUR
Нижче медіани на: 42%
Продавець: cardshop_de (score 540, 99.1%)

Ліквідність (власний proxy, вікно 30 дн.):
  рівень: UNKNOWN — невідомо
  ...
  ⚠ ПЕРЕВІР реальні продажі перед купівлею:
  https://www.ebay.de/sch/i.html?_nkw=Pokemon+151+Elite+Trainer+Box&LH_Sold=1&LH_Complete=1&_sop=13

https://www.ebay.de/itm/226099887766
```

**Як читати заголовок:**

| Заголовок | Що означає |
|---|---|
| `PRICE OK · LIQUIDITY OK` | дешево **і** швидко продається — найкращий сигнал |
| `PRICE OK · LIQUIDITY MEDIUM` | дешево, попит помірний |
| `PRICE OK · LIQUIDITY LOW` | дешево, але **майже не купують** — гроші заморозяться |
| `PRICE OK · LIQUIDITY UNKNOWN` | дешево, попит ще не оцінено → **обовʼязково перевір sold-посилання вручну** |
| мітка `⚠ … ЗА НАЗВОЮ` | немає epid, товар згруповано за назвою — медіана менш точна |

**Перед покупкою за будь-яким сповіщенням:** відкрий `sold`-посилання з
повідомлення (це фільтр «Завершені: продані» на eBay.de) і подивись, скільки
таких реально продалось за останній місяць і за скільки. Хвилина перевірки.

## 4. Команди керування

Усі — з папки `D:\ebay-bot` (у cmd або PowerShell).

| Дія | Команда |
|---|---|
| **Запустити** | `run.bat` (подвійний клік або в терміналі) |
| **Зупинити** | `stop.bat` |
| **Дивитись лог наживо** | `powershell Get-Content bot.log -Wait -Tail 30` |
| **Звіт розвідки** (будь-коли) | `python main.py --discovery-report` |
| **Один тестовий прогін** | `python main.py --once` |
| **Перевірка ключів** | `python selftest.py` (додай `--telegram` щоб надіслати тест) |
| **Почати збір з нуля** | `python main.py --once --reset-history` (стирає базу!) |
| **Скільки зібрано** | подивись розмір `discovery_log.jsonl` і рядок «Унікальних ключів товару» у `bot.log` |

### Автозапуск при вході в систему

Вже налаштовано: `ebay-bot.vbs` у теці
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` — запускає `run.bat`
приховано (без вікна) при кожному вході в Windows.

Прибрати автозапуск: видалити цей `.vbs` з теки «Автозавантаження».

**Надійніше (потрібні права адміністратора)** — Планувальник завдань. У
PowerShell **від імені адміністратора**:

```powershell
schtasks /Create /TN "ebay-bot" /TR "wscript.exe \"%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\ebay-bot.vbs\"" /SC ONLOGON /RL LIMITED /F
```

## 6. Ключові налаштування (`.env` або `config.py`)

| Параметр | Зараз | Що робить |
|---|---|---|
| `DISCOVERY_MODE` | `true` | true = збір без Telegram; false = бойові сповіщення |
| `DISCOVERY_PERIOD_DAYS` | `7` | орієнтир, коли дивитись `--discovery-report` |
| `POLL_INTERVAL_SECONDS` | `1800` | пауза між прогонами (30 хв) |
| `ANOMALY_THRESHOLD` | `0.6` | аномалія, якщо ціна < поріг × історична медіана |
| `MIN_HISTORY_POINTS` | `3` | мін. спостережень на товар перед аналізом |
| `MIN_SELLER_FEEDBACK_SCORE` / `_PCT` | `10` / `95` | фільтр репутації продавця |
| `SEARCH_LIMIT` | `200` | розмір відповіді API (макс), на бюджет не впливає |

Бюджет запитів: `2 виклики × 34 категорії × 48 циклів/добу` = **3264/добу**
проти ліміту eBay **5000/добу** (~65%). Додаси категорій — стеж, щоб
`2 × N × 48` не перевищило ~4500; інакше піднімай `POLL_INTERVAL_SECONDS`.

## 7. Додати нову категорію

1. Підбери `min_price` живим запитом (нижня межа реальної ціни ЦЬОГО товару).
2. Додай рядок у `CATEGORIES` (`config.py`):
   `{"query": "...", "min_price": <N>},`
3. Запит має описувати **один товарний ряд** (`LEGO 10307`, а не `LEGO Set`) —
   інакше під одним ключем сотні різних товарів і історія не набереться.
4. `stop.bat` → `run.bat`.

## 8. Призначення

Інструмент для **особистого моніторингу цін**. Не для автоматичних масових
закупівель, покупок не робить. Метрика ліквідності наближена — не замінює
ручну перевірку завершених продажів. Регулярний масовий перепродаж —
узгоджувати з правилами eBay щодо dropshipping і оформлювати як бізнес.
