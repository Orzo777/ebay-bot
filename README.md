# ebay-bot — купівля на Kleinanzeigen/eBay і перепродаж на eBay.de

Особистий інструмент перепродажника (Гамбург, бюджет ~1 000 €): знаходить вигідні RAM і консолі (PS5, Xbox Series X,
Switch) у приватних продавців, відсіює шахраїв, веде облік, готує оголошення на продаж і сам стежить за своїм здоров'ям.
Продавцям нічого не пише сам — тексти лише копіюються в один дотик.

## Три Telegram-боти

| Бот | Що там |
|---|---|
| **Основний** (`TELEGRAM_BOT_TOKEN`) | Лише покупки: картки з Kleinanzeigen і eBay, аукціони в останні хвилини, оцінка посилань («поділитися»), відповіді продавців KA з перекладом |
| **«Облік і продаж»** (`OFFICE_BOT_TOKEN`) | Облік (`купив` / `продав` / `облік`), `продати N`, `виставив N`, `звіт`; щоденний звіт 9:00, тижневий — щопонеділка; сторож і сторож цін |
| **ПК-бот** (`PC_BOT_TOKEN`) | Дешеві ПК у Гамбурзі з окремої підписки KA |

## Як усе з'єднано

```
Kleinanzeigen (збережені пошуки) ──лист──► Gmail ──► Apps Script check() щохвилини ──► GitHub ram_mail_alert ──► картка
eBay Browse API ◄── ebay_watch (крутиться без перерви, ланцюжком по 55 хв) ─────────────────────────────────────► картка
Telegram «поділитися» ──► Apps Script doPost ──► GitHub ka_share ──► відповідь у той самий чат
бот «Облік і продаж» ──► doPost ?bot=office ──► ledger.gs (Google-таблиця) ──► sell.yml / weekly_report.yml (зашифровано)
Gmail: листи eBay/KA про покупки й продажі ──► ledger.gs кожні 15 хв ──► таблиця «Облік перепродажу»
Gmail: відповіді продавців KA ──► kafilter.gs кожні 5 хв ──► шахраї в кошик, чесні — у бот
сторож: watchdog.gs кожні 10 хв (GitHub, пошта, токен, тригери, версії файлів) + незалежна перевірка в ebay_watch
сторож цін: price_refresh щодня ──► research/ram_prices.json (стелі купівлі RAM і консолей)
```

## Файли

**research/** — робочий код (Python, запускається в GitHub Actions)

| Файл | Роль |
|---|---|
| `ram_alert.py`, `console_alert.py`, `../ram_parse.py` | Оцінка: тип товару з назви, ціни продажу (Terapeak + сторож цін), стелі, вердикт, текст картки й продавцю |
| `ka_listing_check.py` | Сторінка оголошення KA: шахрайство, дефекти, поточна ціна, фото |
| `ram_mail_check.py` | Листи KA з Gmail (IMAP) → картки |
| `ebay_watch.py` | eBay: нові «Sofort-Kaufen», зниження цін, аукціони; щогодини — незалежний сторож і запуск сторожа цін |
| `ka_share.py` | «Поділитися → бот»: оцінка будь-якого посилання KA / eBay |
| `photo_check.py` | Фото → Gemini: чи збігається з назвою (наклейка RAM, модель консолі) |
| `sell.py`, `weekly_report.py`, `daily_report.py` | «продати N», тижневий і щоденний звіти |
| `price_refresh.py` | Сторож цін: щоденний зсув цін продажу разом з ринком, сповіщення, місячний пошук нових категорій |
| `health.py` | Погодинні лічильники в станах ботів і службові повідомлення |
| `pc_alert.py` | ПК-бот |

**tools/** — Google Apps Script (вставляється вручну в проєкт script.google.com, див. нижче) і їхні тести на node

| Файл у репо | Файл в Apps Script | Що робить |
|---|---|---|
| `gmail_trigger.gs` | `code.gs` | `check()` — сигнал «є лист KA»; `doPost` — вебхук обох ботів |
| `ledger.gs` | `ledger.gs` | Облік у Google-таблиці, команди бота «Облік і продаж», «продати», тижневий звіт |
| `kafilter.gs` | `kafilter.gs` | Відповіді продавців: шахраї в кошик, чесні — у бот з перекладом |
| `watchdog.gs` | `watchdog.gs` | Сторож кожні 10 хв, щоденний звіт, перевірка версій файлів |

**Корінь:** `main.py` (клієнт eBay API), `config.py`, `check.py` + `econ_model.py` (ручний інструмент «перевір»), тести `test_*.py`.
**archive/** — старий сканер eBay (зупинено 23.09), разові дослідження, старі документи. У роботі не використовується.

## Секрети

GitHub → Settings → Secrets → Actions: `EBAY_APP_ID`, `EBAY_CERT_ID`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
`OFFICE_BOT_TOKEN`, `PC_BOT_TOKEN`, `GEMINI_API_KEY`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`.

Apps Script → ⚙ «Властивості скрипту»: `GITHUB_TOKEN` (fine-grained, лише цей репозиторій, Actions: read and write),
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `OFFICE_BOT_TOKEN`, `GEMINI_API_KEY`; `LEDGER_ID` створює `setupLedger()`.
Токени — лише у властивостях, не в коді: оновлення файлу з репозиторію стирає код.

## Оновлення Apps Script

1. Сторож щоранку порівнює версії (`VER_*`) з GitHub і сам пише в бот «Облік і продаж», який файл замінити.
2. Заміна: GitHub → файл → Raw → скопіювати все → вставити в Apps Script → 💾.
3. Якщо змінено `code.gs` або `ledger.gs` (там обробка повідомлень ботів) — «Ввести в дію» → «Керування розгортаннями»
   → ✏ → «Нова версія» → «Ввести в дію». Адреса не змінюється.

Розробнику: змінив `tools/*.gs` → підніми його `VER_*` і онови `tools/versions.json` (`node tools/test_versions.js` підкаже).

## Ліміти й уроки

- **Gmail (Apps Script і IMAP):** ніколи не перечитувати всю пошту щоразу — лише нове (`after:`, заголовки). 01.10 ліміт
  Google вичерпався, і листи KA приходили пачками із запізненням.
- **eBay Browse API:** 5 000 викликів на добу на всіх (eBay-сторож ~2 400, сторож цін ~35, «продати»/звіти — одиниці).
- **Репозиторій публічний:** у логи — жодних сум і даних обліку; облік передається в GitHub зашифрованим токеном бота.
- **Тести** фіксують ціни Terapeak (`RAM_PRICES_OFF=1`), бо сторож цін змінює `ram_prices.json` щодня.
